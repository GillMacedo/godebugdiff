Note: With go 1.27, the go command needed to add requirements to go.mod, as `go mod tidy` would. godebugdiff did that in a temporary copy from the module cache, so expect go.mod changes with the bump.

Note: This module has no main package, so these are its test binaries. A library's go line doesn't set GODEBUG for programs that import it: they use their own go.mod. Raising it does make those programs need Go 1.27 or newer, which raises their go line too.

Note: Crossing Go 1.22 also changes the language: each loop iteration gets its own loop variable in this module's code. That isn't a GODEBUG setting, so it isn't listed above. See https://go.dev/blog/loopvar-preview.
